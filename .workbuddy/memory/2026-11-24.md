### 行业调研：桩端/平台金额不一致的通行做法（用户要求查互联网）
- **充电行业特有**：电表(交流进线) vs 桩计费模块(直流输出)天然差 3~5%（整流+枪线损耗）；计量精度容忍 ±2%；后台手算金额误差 >0.1元/单说明逻辑异常；合同惯例是电量以桩端电表为准，不用后台电量替代。
- **OCPP 计费数据完整性**：计费前设 integrity gate（起止读数存在/电量单调递增/时长合理/meter delta 匹配），不过关进 quarantine queue + reason code；订单状态 active/completed/pending-review/billed，billed 后不可变、更正走关联调整记录；产生金额的事件全幂等；保留原始报文作争议证据。（AmpNexus / RIOD）
- **对账容差**：tolerance matching 是标准做法（减少 exception queue 15~30%）；最安全是**绝对 AND 百分比取更小者**；硬排除（单笔大额/编号不符/无法识别）绝不自动通过；每次自动容差须记录 rule/variance/timestamp 审计；自动核销要有 GL 科目归属；异常分 提示/待确认/阻断/紧急 四级；**没有已知原因的差额即使很小也应进异常队列，不自动归零**。（Zuora / Terra Insight / Tech Capital Hub / XTransfer）
- **EV 结算**：OCPP 整数 Wh + 货币 2 位小数，舍入永远不净为零；"reconciliation exists to explain it, not eliminate it"；需 immutable session ID + tariff version + metered/priced/captured/settled 状态。（YoCharge / Elinta）
- **对用户规则的评估**：纯绝对 0.01 元容差——大额订单过严、小额过松、分段舍入累积可能偏紧；"差额小就自动过"缺归因要求；P>D 时用户比桩端屏显多付 1 分有投诉风险（人民网报道消费者会核对两者）。建议改为组合容忍 min(0.01元, 0.1%×订单额)+归因+审计留痕。

## 修复：真实桩心跳"收不到"（2026-11-25 15:25）
